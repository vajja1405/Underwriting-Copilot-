### F1. freMTPL2: claims without amounts, concentrated in one IDpol block

- Severity: High (would bias the frequency model)
- Evidence: 9,116 policies with claims have no severity rows (26.8% of claims). Every one of the 9,387 policies with IDpol below 24,952 has a claim. On test policies outside that block, observed / predicted claims were 0.743 (GLM) and 0.756 (LightGBM) for models fitted on the recorded counts, against 1.007 and 1.005 for the chosen treatment.
- Action / status: Claims without a recorded amount are not counted for modelling (same treatment as the scikit-learn Tweedie example); the alternative is reported as a sensitivity analysis.

### F2. German Credit: the dataset documentation mislabels the sex codes

- Severity: High for the fairness demonstration
- Evidence: german.doc labels attribute 9 (personal status and sex) wrongly. The corrected code table published with the South German Credit data (Groemping 2019, Report 4/2019, Beuth University of Applied Sciences Berlin; UCI 2020, doi:10.24432/C5QG88) has the same row counts per code and gives: A91 male divorced/separated, A92 female non-single or male single, A93 male married/widowed, A94 female single. The 'sex' comparison follows german.doc (the convention in most fairness work) and so groups some single women as male and some single men as female; treat it as a demonstration of the method, not a measurement of sex disparity. 'sex_corrected_codes' uses only the unambiguous codes.
- Action / status: The primary comparison follows german.doc (the usual convention in fairness work) and carries this warning; a sensitivity comparison uses only the unambiguous corrected codes.

### F3. Severity: LightGBM is not measurably better than the Gamma GLM

- Severity: Low
- Evidence: Paired difference in mean Gamma deviance -0.0024 [-0.0135, 0.0089] (includes 0).
- Action / status: Serve the model preferred on validation (GLM); revisit with more claims.

### F4. Severity models rank claims only weakly

- Severity: Medium
- Evidence: Severity Lorenz Gini: GLM 0.0358 [0.0033, 0.0699], LightGBM 0.0252 [-0.0067, 0.0578]; the interval includes 0 for: LightGBM.
- Action / status: Expected-loss ranking comes mostly from frequency; severity is close to a portfolio average. State this in any use of expected loss.

### F5. Fairness demo: the test set is too small to rule out a four-fifths breach

- Severity: Medium
- Evidence: AIR 95% intervals that contain 0.8: logistic regression: age_lt25; logistic regression: age_le30; logistic regression: sex_corrected_codes; LightGBM: sex; LightGBM: age_lt25; LightGBM: age_le30.
- Action / status: Report intervals, never point estimates alone; a real test needs far more applicants per group.

### F6. Fairness demo: some intervals exclude no difference (multiple comparisons, unadjusted)

- Severity: Medium (possible disparity, to investigate)
- Evidence: logistic regression, age_le30 (sensitivity comparison, 131 unprivileged applicants): equal-opportunity difference -0.115 [-0.225, -0.009] excludes 0 and adverse impact ratio 0.823 [0.696, 0.956] excludes 1. These come from 16 intervals (an adverse impact ratio and an equal-opportunity difference for every model and comparison), each at 95% and with no adjustment for multiple comparisons, so about one in twenty would exclude the no-difference value by chance alone even if no disparity existed.
- Action / status: The flagged rows are pre-declared sensitivity comparisons; the primary comparisons' intervals all include the no-difference value. Not read as a measured disparity, and not dismissed: a real assessment would fix one primary comparison per protected characteristic in advance, adjust for multiple comparisons, and test on far more applicants. The sex-coding warning does not apply to age comparisons.

### F7. Excluding protected attributes does not hide them

- Severity: Medium
- Evidence: Test AUC of predicting group membership from the credit model's own features: sex 0.704 [0.641, 0.766]; age_lt25 0.810 [0.750, 0.863]; age_le30 0.834 [0.789, 0.880]; sex_corrected_codes 0.774 [0.664, 0.869].
- Action / status: Outcome testing (AIR, equal opportunity) is needed even when protected attributes are not features; proxy features need review.

### F8. Severity calibration misses in some deciles (GLM)

- Severity: Low
- Evidence: Deciles whose predicted mean lies outside the observed 95% CI: decile 1: predicted 1308.6059, observed 1708.1512 [1406.2731, 2037.2858].
- Action / status: Total calibration is checked separately; watch these deciles in monitoring and consider recalibration if the pattern persists.

### F9. Insurance models have no out-of-time test

- Severity: Medium
- Evidence: not measured (freMTPL2 has no date or policy-year field, so an out-of-time test is impossible. Train, validation and test are random draws from the same period; the test metrics do not show how the models would hold up on a later year.)
- Action / status: Monitoring (PSI, observed / predicted by period) must start as soon as dated data exists.

### F10. LightGBM frequency is not monotonic in BonusMalus

- Severity: Low
- Evidence: Adding 10 to BonusMalus lowered the predicted frequency for 5.37% of 135,603 test policies.
- Action / status: Acceptable for a demonstration; a production model could add a monotone constraint for this feature and compare deviance.

### F11. Large-loss cap removes a material share of claim cost

- Severity: Medium
- Evidence: The cap at 34,328.39 affects 0.51% of training claims but removes 29.3% of the training amount.
- Action / status: Expected loss is on a capped basis; pricing would need a separate large-loss loading.

### F12. Results were produced from uncommitted code

- Severity: Medium (reproducibility)
- Evidence: The provenance of `insurance_frequency`, `insurance_severity`, `fairness_demo` records git commit `bbedb8d30fa8f4d761a926d70c61cf25d7771743` with uncommitted changes outside results/, so that commit alone does not contain the code that produced these numbers.
- Action / status: Commit the code, rerun `make phase1` from the clean tree so git_worktree_dirty is false, and commit the regenerated results and documents. This finding disappears when that is done.

## 7. Limitations of this validation

- Not independent (see above).
- One public dataset per model; nothing here says how the models would perform on any lender's or insurer's portfolio.
- No production data, so no monitoring results exist yet; the monitoring plans are in the model cards.

Applicability of any guidance cited here depends on the institution and its risk profile. This project is a demonstration, not a compliance program, and nothing in it claims compliance with any regulation or guidance.
