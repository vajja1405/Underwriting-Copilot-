Thresholds (config/monitoring.yaml; every value is a design choice)

checkrulerationale
input_drift_psihigher_is_worse: warn 0.1, alert 0.25The same bands as risk/stability.py and the model cards (stable < 0.10 <= moderate shift <= 0.25 < significant shift). A common industry rule of thumb, not a statistical test.
score_drift_psihigher_is_worse: warn 0.1, alert 0.25Same bands as the input PSI, so one scale reads every PSI in the report.
calibration_ecehigher_is_worse: warn 0.015, alert 0.025Equal-count bins, because most policies have no claim and equal-width bins would put almost every policy in the first bin. With 5,000 policies per window a bin holds 500 policies at a claim share of a few percent, so binomial noise alone keeps the ECE of every window above zero; the warn and alert levels were set above the size that noise was expected to have (the ECE of every demonstration window is in the results).
calibration_ratioband [0.9, 1.1], 0.95 interval, min 50.0 predicted claimsA +/-10% tolerance on the claim level is a round pricing tolerance. "warn" when the point estimate leaves the band; "alert" only when the whole 95% interval lies outside it, so the random noise of one window should rarely alert (the false alert rate actually measured is in the results). Below 50 predicted claims the check reports insufficient_data instead of a level.
citation_support_ratelower_is_worse: warn 0.995, alert 0.99Share of extracted values whose cited page prints the value (results/docintel_metrics.json rules.citations.supported_all_values). One unsupported citation in 100 is the alert level.
ocr_page_sharehigher_is_worse: warn 0.25, alert 0.4Share of pages with no text layer that had to be read by OCR (the OCR fallback). Field accuracy is lower on scanned pages, so a growing share is an early warning about the input mix.
low_confidence_field_sharehigher_is_worse: warn 0.05, alert 0.1Share of extracted fields below the extractor's confidence cut. Kept so the rule exists when the metric does; results/docintel_metrics.json has no field-confidence metric today.
required_escalations_escalatedlower_is_worse: alert 1Every case that must reach a senior human (sanctions potential match, detected injection, policy referral) must be escalated; anything below 100% is a breach (results/agent_metrics.json).
unsupported_claim_ratehigher_is_worse: warn 0.01, alert 0.02Share of memo claims with no supporting citation. Needs an LLM run; not measured in this checkout.
override_ratehigher_is_worse: warn 0.1, alert 0.2Share of reviewed decisions where the reviewer overrode the recommendation, read from the "feedback" section of results/governance_metrics.json (SIMULATED reviewer decisions). A high rate says reviewers often disagree with the system.

Limitations

  • freMTPL2 has no date or policy-year field, so no real stream of new business and no out-of-time split exist. Windows are random draws from the held-out split and every drift is INJECTED (SYNTHETIC scenarios).
  • All streams draw from one held-out pool of policies, so they are not independent samples of the world; the bootstrap intervals describe stream-to-stream variation for this pool and this model.
  • A window is an independent random draw (without replacement inside the window), so a policy can appear in two windows of one stream.
  • Outcomes are assumed known at the end of each window (no claim reporting lag, no IBNR); a real book sees claims months later, which adds that lag to every calibration detection delay.
  • Thresholds are design choices (config/monitoring.yaml), not fitted limits. The detection results hold for these scenarios, this window size and this model only.
  • The extraction, agent and reviewer indicators are single values read from the latest results files, not a stream; they cannot show drift over time.
  • Demonstration only: not a production monitoring system and not a compliance programme. Whether and how any monitoring expectation applies depends on the institution and its risk profile.
